Experiment logging convention

How training, inference, benchmark, and deployment runs are saved so results stay traceable and comparable.

Getting started · Dependencies

Goals

  • Every run records the exact config that produced it.
  • Directories are timestamped and grouped by experiment kind.
  • Metrics use a consistent JSON file for later comparison.
  • Large artifacts stay gitignored under runs/ and outputs/.

Directory layout

Experiment runs (runs/)

runs/
├── inference/          # offline inference and dummy pipeline runs
│   └── <run_id>/
├── finetune/           # LoRA / supervised training runs
│   └── <run_id>/
├── benchmark/          # latency and throughput measurements
│   └── <run_id>/
└── deploy/             # quantization and export experiments
    └── <run_id>/

Each run directory contains:

File / folder Purpose
config.yaml Resolved configuration after defaults merge and validation
metadata.json Timestamp, Lite-VLA version, Python/platform, git commit, optional torch info
metrics.json Run-specific measurements and status
artifacts/ Checkpoints, exported models, plots (created empty at run start)

Incidental outputs (outputs/)

Use outputs/ for non-run artifacts such as camera frame dumps (ros.frame_save_dir in config). These paths are gitignored but are not managed by litevla.experiment.

Run ID naming

Run IDs are UTC timestamps: YYYYMMDDTHHMMSS (example: 20250617T143022).

With a label, the slugified label is prepended: dummy-pipeline_20250617T143022.

  • Labels are lowercased; spaces and punctuation become -.
  • Labels must contain at least one alphanumeric character.
  • Do not put secrets or absolute home paths in labels.

Metadata schema (metadata.json)

Field Description
run_idDirectory name for this run
kindinference, training, benchmark, or deploy
created_atISO-8601 UTC timestamp
litevla_versionPackage version
python_versionInterpreter version
platformOS and machine string
hostnameMachine hostname
gitcommit, branch, dirty
torchVersion and CUDA info when torch is installed
config_pathSource config file path, when known

Metrics schema (metrics.json)

Always include status (success or failed) and duration_ms when timing matters.

Kind Suggested keys
inferenceactions, mode, model_path
trainingepoch, step, loss, val_loss, seed
benchmarkiterations, warmup, latency_ms_mean, latency_ms_p95, device
deployquantization, model_size_mb, export_format

Python API

from litevla.config import load_config
from litevla.experiment import ExperimentRun

config = load_config("configs/default.example.yaml")

with ExperimentRun(
    "inference",
    config,
    label="baseline",
    config_path="configs/default.example.yaml",
) as run:
    run.write_metrics({"status": "success", "duration_ms": 42})

Helpers: run_directory, make_run_id, save_config_snapshot, save_metadata, save_metrics, collect_metadata.

Example: dummy pipeline

python scripts/run_dummy_pipeline.py --log-run --run-label dummy-pipeline

Creates runs/inference/<run_id>/ with config, metadata, and metrics.

Comparing runs

  1. Open each run's metadata.json for git commit, torch version, and config path.
  2. Diff config.yaml files for parameter changes.
  3. Compare numeric fields in metrics.json.
