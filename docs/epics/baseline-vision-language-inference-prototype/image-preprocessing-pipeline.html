Image preprocessing pipeline

Architectural walkthrough of litevla.preprocessing — the camera-frame contract between OpenCV capture and SmolVLM vision input.

Summary · Mental model · Contract · Implementation · Verification · Learning

Executive summary

litevla.preprocessing owns the camera-frame contract between OpenCV capture and the SmolVLM vision encoder. It converts simulation or ROS camera frames (BGR numpy arrays) into model-ready tensors or in-memory JPEG/PNG bytes with consistent size, color order, and encoding.

Downstream modules depend on this layer so they never re-implement BGR→RGB swaps, resize rules, or compression logic. Getting color order wrong silently inverts red and blue in the visual embedding space.

Mental model

Think of this module as a camera adapter between robot vision hardware and a pretrained VLM.

  • Exists because VLMs expect RGB at fixed resolutions; OpenCV delivers BGR at arbitrary sizes.
  • Tension fidelity vs latency (JPEG vs raw arrays).
  • Beginner mistake passing BGR directly because previews still look fine.
  • Senior watchpoint channel order, resize aspect ratio, bytes vs PIL consumer.

Backstory

Scattered inline resize logic made channel-order bugs likely. A central ImagePreprocessor with fail-fast config validation is the chosen design — an ETL boundary for sensor data.

Implementation breakdown

Config and validation

if self.color_format not in {"rgb", "bgr", "gray"}:
    raise PreprocessingError(f"Unsupported color format: {self.color_format}")

Notice: Invalid config fails at startup, not on first frame.

Color, resize, encode

if self.color_format == "rgb":
    processed = cv2.cvtColor(image, cv2.COLOR_BGR2RGB)
processed = cv2.resize(processed, (self.resize_width, self.resize_height),
                       interpolation=cv2.INTER_LINEAR)
success, encoded_img = cv2.imencode(ext, processed)

Engineering principle taught by this task

Treat camera frames like an API with explicit color order, dimensions, and encoding — never assume the model sees what you see on a plot.
