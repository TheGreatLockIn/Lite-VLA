Baseline prompting strategy

Architectural walkthrough of litevla.prompting — LLaVA templates, few-shot demonstrations, and discrete action constraints for SmolVLM.

Summary · Mental model · Contract · Implementation · Verification · Learning

Executive summary

litevla.prompting owns the text-side contract for baseline navigation: five allowed action tokens, versioned system instructions, and few-shot <image> sequencing.

VLMs output free text, not robot commands. Prompting reduces conversational hallucinations; Epic 103 parser and safety gate still treat output as untrusted.

Mental model

Think of this module as a compiler from navigation intent to multimodal chat format.

  • Tension: constraint vs expressiveness; few-shot adds latency.
  • Beginner mistake: assuming the system prompt guarantees valid tokens.
  • Senior watchpoint: <image> count matches image tensors; ALLOWED_ACTIONS sync with schema.

Implementation breakdown

Shared vocabulary

ALLOWED_ACTIONS = ("MOVE_FORWARD", "TURN_LEFT", "TURN_RIGHT", "STOP", "SLOW_DOWN")

Formatter

return f"USER: <image>\n{self.system_instruction}\n\n{goal_text}\nASSISTANT:"

Notice: Few-shot omits system block on later examples; paths returned for reference frames only.
