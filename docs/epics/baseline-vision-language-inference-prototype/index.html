Story 1023: Select starter vision-language model

Intent
Pick a model suitable for baseline local inference.
Implementation Walkthrough
Evaluated candidates and selected SmolVLM-256M-Instruct (HuggingFaceTB/SmolVLM-256M-Instruct) for edge deployment. The vision backbone is SigLIP (93M), the language backbone is SmolLM2 (135M), and the cross-modal perceiver resampler projection maps them together (28M), summing to 256M parameters.
Data And Control Flow
Inputs: Camera image + text goal instruction.
Outputs: Text token prediction corresponding to discrete actions.
Hardware: Requires < 1.0 GB VRAM during active inference, enabling parallel execution alongside Webots rendering pipeline on 12GB RTX 4080 GPU.
ADR Notes
Decision: Adopted SmolVLM-256M-Instruct due to its lightweight footprint, native GGUF conversion support, and permissive Apache 2.0 license.
Alternatives Rejected: Moondream2 (0.5B) (kept as fallback; requires custom python loaders), Llama-3.2-1B-Vision (rejected due to excessive VRAM/latency for real-time 6.6Hz loop), OmniVLM (968M) (rejected due to high deployment risk on edge environments).
Validation
Successfully verified GGUF weights locally in LM Studio. Conducted visual recognition smoke checks on a test screenshot, confirming appropriate visual detection capability and action alignment.
Completed

Story 1024: Create image preprocessing pipeline

Intent
Prepare camera frames for the selected model. Deliverable: image-preprocessing-pipeline.html
Implementation Walkthrough
Updated configuration required fields in litevla/config/schema.json and added default parameters to litevla/config/loader.py. Exceeded standard config in configs/default.example.yaml.
Created litevla/preprocessing.py implementing the ImagePreprocessor class, which takes BGR images, performs RGB color channel swapping, resizes using bilinear interpolation, and supports in-memory compression (JPEG or PNG bytes) to match LLaVA requirements.
Data And Control Flow
Input: OpenCV BGR image array (H, W, 3) from ROS topic /image_raw.
Output: Preprocessed, resized, channel-swapped array (H, W, 3) or compressed byte buffer (JPEG/PNG).
Data Paths: Raw Array ➔ Color Space Swapper ➔ Resizer ➔ OpenCV In-Memory Encoder ➔ model-ready JPEG/PNG bytes.
ADR Notes
ADR: In-Memory Compression
Status: Accepted
Context: llama-cpp-python multimodal loading accepts JPEG/PNG files or file byte buffers, not raw NumPy matrices.
Decision: Compress resized frames in memory to JPEG/PNG bytes using cv2.imencode, bypassing SSD/disk storage to optimize latency.
Validation
Created test suite in tests/test_preprocessing.py. Tests verify config schema loading, dimension resizing, channel order correctness, grayscale conversion, and byte-array decoding validation.
Completed

Story 1025: Design baseline prompting strategy

Intent
Write prompts that constrain the model to valid actions. Deliverable: prompting-strategy.html
Implementation Walkthrough
Created litevla/prompting.py containing the allowed discrete action list, prompt versions, and the structured FEW_SHOT_EXAMPLES dictionary references.
Implemented the PromptFormatter class that handles template loading, validations, and provides two main interfaces: format_prompt for zero-shot inference and format_few_shot_prompt for compiling multi-image in-context demonstrations.
For prompt template versioning (VLA-159), added a prompt_version setting to the configuration schema (schema.json) and loader defaults (loader.py). Integrated metadata extraction into the ExperimentRun context manager to log the configured prompt version in metadata.json for every run.
Data And Control Flow
Inputs: Goal instruction string + live camera image frame + configuration settings (including prompt_version).
Outputs: Compiled multi-image prompt string featuring sequential <image> tags + ordered list of target reference image paths.
Flow: Text prompt is dynamically assembled with intermediate USER: <image>\n[instruction]\nASSISTANT: [action] turns. The resulting tuple enables the model backend to load reference images in sequence and inject their embeddings into the correct token indices. The active prompt template version is passed through configuration and serialized in the experiment run metadata block.
ADR Notes
ADR: Discrete Action Constraints & Multi-Image In-Context learning
Status: Accepted
Context: VLMs require strict constraints to avoid text hallucinations. For complex Webots arena steering, text instructions are often insufficient without visual frame references. We need to support multi-modal few-shot demonstrations.
Decision: Restrict VLM actions to five discrete tokens. Compile prompts dynamically with in-context multimodal demonstrations, mapping chronologically ordered reference images (representing centered, left, right, and stop states) to their actions.
Validation
Implemented 8 unit tests in tests/test_prompting.py validating action list integrity, formatting structure, version loading constraints, and few-shot multi-image/prompt compilation. Added config schema checks in tests/test_config_loader.py and logging assertions in tests/test_experiment_logging.py to verify that the prompt version is correctly parsed and recorded. Ran the full test suite via pytest; all tests passed successfully.
Completed

Story 1026: Implement baseline inference wrapper

Intent
Create a callable wrapper around the starter VLM. Deliverable: inference-wrapper.html
Implementation Walkthrough
Created litevla/inference.py implementing the InferenceWrapper class. It initializes `AutoModelForImageTextToText` using target device mapping and PyTorch precision selection (e.g., torch.bfloat16 for CUDA to leverage hardware Tensor Cores, and torch.float32 for CPU).
The execution method infer() handles BGR-to-RGB conversion, PIL image format routing, zero-shot/few-shot prompt formatting, greedy generation constraints (do_sample=False), and final token slicing.
Data And Control Flow
Inputs: OpenCV BGR image numpy array (H, W, 3) from camera loop + text goal instruction string.
Outputs: A structured dictionary payload containing the predicted string action, a timing dictionary (preprocessing, prompting, inference, and total milliseconds), a success boolean, and an optional error string.
Flow: Raw BGR Image ➔ Preprocessor ➔ PIL Image. Prompt Formatter ➔ LLaVA Prompt. Text + Image Tensors ➔ VLM Forward Pass ➔ Decoded Action String. If VLM throws an exception, catches it, logs stack trace, and returns "STOP" fallback.
ADR Notes
ADR: Model Class Binding
Status: Accepted
Context: AutoModelForVision2Seq is missing in the local transformers version, but AutoModelForImageTextToText is fully supported for Idefics3/SmolVLM architectures.
Decision: Use AutoModelForImageTextToText inside InferenceWrapper to maintain local compatibility.

ADR: Safety Recovery Boundary
Status: Accepted
Context: A VLM crash or CUDA OOM spike could stall the robot loop, leading to uncontrolled operations if the last commanded velocity remains active.
Decision: Trap all execution exceptions, log traceback to stdout, and cleanly return action: "STOP", success: False to force immediate deceleration.
Validation
Implemented 9 unit tests in tests/test_inference.py validating dummy execution paths, few-shot reference loads, mock token processing, and exception fallbacks. Ran test suite: pytest tests/test_inference.py -v; all tests passed successfully.
