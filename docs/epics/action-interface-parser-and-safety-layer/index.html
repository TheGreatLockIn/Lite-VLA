Epic 103

Action Interface, Parser, and Safety Layer

Define safe structured actions and convert model text into bounded robot commands.

Intent | Epic pipeline | Stories | ADR log

Epic Intent

Context: The VLA model emits text. The robot needs bounded, repeatable velocity commands on ROS /cmd_vel. This epic owns everything between raw model output and a safe geometry_msgs/Twist.

Scope: Discrete and optional continuous action schemas, parsers that normalize noisy text, velocity clamps, fallback STOP on invalid output, and command smoothing between inference steps.

Success criteria: Invalid model output maps to STOP; velocity limits are enforced; parser has unit tests; the discrete action schema is documented and shared via litevla.actions.

Current progress: Stories 1017, 1019, 1021, and 1022 (discrete path through safety gate and smoothing) are complete. Stories 1018 and 1020 are planned — see each task card.

Story 1017: Define discrete action schema

Intent
Owns the discrete action contract: five exact tokens and nominal (linear_x, angular_z) mapping via litevla.actions. Downstream parser, safety, dataset, and ROS code import this module — they do not define parallel vocabularies.
Implementation Walkthrough

Full walkthrough: Discrete action schema (action-schema.md for agents).

Vocabulary + nominal profile — DiscreteAction enum and ACTION_VELOCITIES in litevla/actions/schema.py. Design: single source of truth for labeling and runtime. Risk: enum renames break datasets.

Validation + clamp primitives — is_valid_action, clamp_velocity. Design: non-throwing probe + reusable axis clamp for Story 1021. Risk: whitespace normalization deferred to Story 1019.

Mapping API — action_to_twist(action, *, max_linear_vel, max_angular_vel). Design: required config limits; fail-fast on unknown tokens. Risk: ValueError must not reach /cmd_vel without Story 1021.

Integration — scripts/run_dummy_pipeline.py iterates ACTION_NAMES with config safety limits; replaced ad-hoc FORWARD/STOP placeholders.

Data And Control Flow
token ──> ACTION_VELOCITIES ──> clamp_velocity ──> (linear_x, angular_z)

Contract: exact token in; clamped SI velocities out. Invariant: every enum member has one nominal pair. Trade-off: nominal semantics stable for training; config tightens deployment limits.

ADR Notes

ADR: Five-token discrete vocabulary — Accepted. Discrete-first for MVP; JSON velocity path secondary. Rejected FORWARD alias and continuous schema as primary path.

Verification Patterns

Contracts defended: stable token order, complete velocity table, MVP design-point values, config clamping, alias rejection, fail-fast on invalid tokens, config integration via dummy pipeline.

python scripts/run_dummy_pipeline.py

Story 1019: Implement discrete action parser

Intent
Extract a valid DiscreteAction token from noisy VLA text (whitespace, punctuation, lowercase variants) before calling action_to_twist.
Implementation Walkthrough

Full walkthrough: Discrete action parser (discrete-action-parser.md for agents).

Normalization (10058) — normalize_action_text and _strip_trailing_punctuation in litevla/actions/parser.py. Design: strip, uppercase, trim trailing ./! on whole-string candidates. Risk: leading punctuation relies on regex fallback.

Parser (10057) — parse_discrete_action(text) -> DiscreteAction | None. Exact match fast path, then _ACTION_TOKEN_PATTERN word-boundary search built from ACTION_NAMES. Design: returns None on failure; Story 1021 maps to STOP. Risk: multiple tokens return first match only.

Tests (10059) — tests/test_action_parser.py covers exact, noisy, invalid, and multi-token inputs.

Data And Control Flow
VLA text ──> parse_discrete_action ──> DiscreteAction | None ──> action_to_twist / safety gate

Contract: raw string in; known token or None out. Invariant: vocabulary matches Story 1017; no aliases. Trade-off: fail reporting here; fail-safe publishing deferred to 1021.

ADR Notes

ADR: Return None on parse failure — Accepted. Safety gate owns STOP fallback (RSK-02). Rejected raising in parser and returning STOP directly.

Verification Patterns
pytest tests/test_action_parser.py -q

Contracts: exact tokens, normalized noise, invalid/alias rejection, first embedded token wins.

Open Questions

  • Log parse failures for baseline eval (Story 1027)?

Story 1021: Implement safety clamp and fallback behavior

Intent
Guarantee unsafe or unparseable commands cannot reach /cmd_vel. MVP acceptance: malformed VLA output becomes zero velocity STOP; velocities stay within config limits (MVP design points 0.2 m/s / 0.6 rad/s).
Implementation Walkthrough

Full walkthrough: Safety clamp and fallback (safety-clamp-and-fallback.md for agents). Learning notes for subtasks 10252 and 10253 are in that doc.

Velocity clamp (10063) — clamp_twist_velocities in litevla/actions/safety.py, reusing clamp_velocity from Story 1017. Design: standalone per-axis clamp with was_clamped flag. Risk: NaN/Inf not validated (same as schema).

Invalid-output STOP (10064) — safe_command_from_text calls parse_discrete_action; on None returns STOP at (0.0, 0.0) without raising. Design: fail-safe at ROS publish boundary (RSK-02). Risk: first embedded token still wins when multiple tokens present.

Safety event logging (10065) — SafetyEvent / SafetyEventKind on every SafeCommand; WARNING logs include original_text on failure and clamp. Design: structured events for tests + logging for live nodes.

Integration — scripts/run_dummy_pipeline.py routes actions through safe_command_from_action and demonstrates invalid-text fallback.

Data And Control Flow
VLA text ──> safe_command_from_text ──> SafeCommand ──> (linear_x, angular_z) ──> /cmd_vel

Contract: raw text or known DiscreteAction in; bounded velocities out. Invariant: no parse failure propagates as an exception. Trade-off: discrete-only MVP; JSON path deferred to Stories 1018/1020.

ADR Notes

ADR: Central safety gate — Accepted. Parser reports failure; safety gate publishes STOP and logs. Rejected STOP inside parser and per-call-site try/except around action_to_twist.

Verification Patterns
pytest tests/test_action_safety.py -q
python scripts/run_dummy_pipeline.py

Contracts: axis clamp, valid text mapping, invalid text STOP, config clamp events, safety logging.

  • Rate-limit safety WARNING logs during baseline eval (Story 1027)?

Story 1022: Add command smoothing

Intent
Reduce jerky command changes when VLA inference runs at ~5 Hz while the low-level controller expects smoother motion (see MVP risk RSK-05).
Implementation Walkthrough

Full walkthrough: Command smoothing (command-smoothing.md for agents). Learning notes for subtasks 10254 and 10255 are in that doc.

Strategy (10066) — per-axis slew-rate limiter toward the latest safe target. Rejected moving average (blends discrete jumps) and fixed lerp (restart complexity). Design: dt-based stepping works at any heartbeat rate.

Rate limiter (10067) — step_toward and CommandSmoother in litevla/actions/smoothing.py. Design: independent linear/angular axes; configurable max_linear_rate / max_angular_rate (per second). Risk: NaN/Inf not sanitized (same as schema/safety).

STOP bypass (10068) — is_stop_bypass snaps to zero immediately for DiscreteAction.STOP, including parse-failure STOP from the safety gate. Design: bypass checks action label, not velocity magnitude.

Integration — scripts/run_dummy_pipeline.py prints a smoothing ramp demo; heartbeat_controller.py applies CommandSmoother each timer tick; config smoothing section in configs/default.example.yaml.

Data And Control Flow
SafeCommand ──> CommandSmoother.step(dt) ──> smoothed SafeCommand ──> /cmd_vel
STOP action ──> immediate (0.0, 0.0), reset state

Contract: clamped target in; rate-limited velocities out; STOP never delayed. Trade-off: tune rates with heartbeat_hz — defaults reach nominal speeds in ~400 ms at 10 Hz.

ADR Notes

ADR: Per-axis slew-rate limiter — Accepted. Stateful smoother after safety gate. Rejected moving average and fixed-duration lerp.

Verification Patterns
pytest tests/test_action_smoothing.py -q
python scripts/run_dummy_pipeline.py

Contracts: max delta per tick, ramp to target, STOP bypass, parse-failure STOP, disabled passthrough, mid-ramp retarget.

Open Questions
  • Raise default heartbeat_hz when smoothing is enabled in sim launches?
  • Expose smoother state on /litevla/diagnostics?

Epic ADR Log

ADR: Discrete-first action interface

Status: Accepted (Story 1017)

Context: MVP must stay beginner-friendly; continuous VLM velocities are explicitly deferred.

Decision: Ship litevla.actions as the shared discrete contract; optional JSON path (1018/1020) is secondary.

Consequences: Training data, prompts, and parser tests target five exact tokens; safety gate enforces bounds on mapped velocities.

ADR: Per-axis slew-rate limiter

Status: Accepted (Story 1022)

Context: VLA inference at ~5 Hz causes step velocity changes; heartbeat runs faster.

Decision: CommandSmoother with per-second rate limits and immediate STOP bypass after the safety gate.

Consequences: Tune smoothing.max_*_rate with heartbeat_hz; ROS heartbeat owns smoother state.
