Epic 103

Action Interface, Parser, and Safety Layer

Define safe structured actions and convert model text into bounded robot commands.

Intent | C4 context | Stories | ADR log

Epic Intent

Context: The VLA model emits text. The robot needs bounded, repeatable velocity commands on ROS /cmd_vel. This epic owns everything between raw model output and a safe geometry_msgs/Twist.

Scope: Discrete and optional continuous action schemas, parsers that normalize noisy text, velocity clamps, fallback STOP on invalid output, and command smoothing between inference steps.

Success criteria: Invalid model output maps to STOP; velocity limits are enforced; parser has unit tests; the discrete action schema is documented and shared via litevla.actions.

Current progress: Story 1017 (discrete action schema) is complete. Stories 1018–1022 are planned and seeded from Jira — see each task card for intended upstream/downstream connections.

Story 1017: Define discrete action schema

Intent
Create the first safe action vocabulary for the navigate-to-cube MVP: five uppercase tokens with a shared nominal velocity table and a single Python module (litevla.actions) that downstream parser, safety, dataset, and ROS code can import.
Implementation Walkthrough

Start here: Discrete action schema task doc (action-schema.md for agents).

litevla/actions/schema.py — core module. Defines design-point constants (DEFAULT_LINEAR_FORWARD, etc.), the DiscreteAction str enum, ACTION_VELOCITIES lookup table, is_valid_action(), clamp_velocity(), and action_to_twist(). The latter is the main runtime API: accept enum or exact string, look up nominal (linear_x, angular_z), clamp with config limits, return floats.

litevla/actions/__init__.py — re-exports the public API so callers use from litevla.actions import ... instead of reaching into schema.py directly.

scripts/run_dummy_pipeline.py — integration demo without ROS. Loads config, iterates ACTION_NAMES, calls action_to_twist with safety limits, prints results. Replaced earlier ad-hoc FORWARD/STOP placeholders.

tests/test_action_schema.py — locks token naming, velocity table completeness, MVP design-point values, config clamping, is_valid_action, and ValueError on bad tokens.

Outputs: clamped (linear_x, angular_z) for ROS Twist or logging.
Future consumers: Story 1019 parser validates text then calls this module; Story 1021 adds STOP fallback and ROS-side enforcement.

ADR Notes

ADR: Five-token discrete vocabulary

Status: Accepted

Context: MVP non-goals defer continuous VLM velocity output; beginners need a small label set.

Decision: Standardize on MOVE_FORWARD, TURN_LEFT, TURN_RIGHT, SLOW_DOWN, STOP with nominal 0.2/0.1 m/s forward and ±0.6 rad/s turns.

Alternatives rejected: FORWARD alias (ambiguous); continuous JSON schema first (harder to train/parse for MVP).

Consequences: Dataset labels and prompts must use exact tokens; parser story validates strings before calling action_to_twist.

Story 1021: Implement safety clamp and fallback behavior

Intent
Guarantee unsafe or unparseable commands cannot reach /cmd_vel. MVP acceptance: malformed VLA output becomes zero velocity STOP; velocities stay within 0.2 m/s / 0.6 rad/s operational limits.
Planned scope

Central safety gate that composes parser output, applies clamps (may reuse clamp_velocity from Story 1017), converts parser failures to STOP, and logs safety events. action_to_twist already clamps per-axis values but does not handle invalid tokens or ROS publish policy — this story owns end-to-end safe publishing.

Upstream: parser (1019) or JSON parser (1020).

Downstream: ROS /cmd_vel publisher; optional smoother (1022).

Implementation Walkthrough
Not started. Foundation: clamp_velocity and action_to_twist in litevla/actions/schema.py.

Not run — story not implemented.
