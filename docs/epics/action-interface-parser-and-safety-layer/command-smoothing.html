Epic 103 · Story 1022

Command smoothing

Per-axis rate limiting between the safety gate and /cmd_vel, with immediate STOP bypass.

Summary · Contract · Learning · Implementation · Decisions · Verification

Executive summary

litevla.actions.smoothing is the rate-limiting layer between the safety gate (Story 1021) and ROS /cmd_vel publishing. It reduces jerky velocity changes when VLA inference updates at ~5 Hz while the heartbeat runs at 10–100 Hz (RSK-05).

Subtasks covered: 10066 (strategy), 10067 (rate limiter), 10068 (STOP bypass), 10254 and 10255 (learning).

Learning notes

Subtask 10254 — Control-rate decoupling

  • Slew rate — max_delta = rate * dt per heartbeat tick.
  • Setpoint tracking — each inference step sets a new target; smoother approaches incrementally.
  • Defaults — 0.5 m/s² and 1.5 rad/s² reach MVP nominal speeds in ~400 ms.

Subtask 10255 — STOP bypass

  • Immediate zero — no ramp-down on emergency or parse-failure STOP.
  • Action label — bypass checks discrete action, not velocity magnitude.
  • Timeout — heartbeat resets smoother on action/camera timeout.

Implementation breakdown

Strategy (Subtask 10066)

Decision: per-axis slew-rate limiter. Rejected moving average (blends discrete jumps) and fixed lerp (restart complexity).

Rate limiter (Subtask 10067)

def step_toward(current: float, target: float, max_delta: float) -> float:
    delta = target - current
    if abs(delta) <= max_delta:
        return target
    return current + math.copysign(max_delta, delta)

STOP bypass (Subtask 10068)

if is_stop_bypass(target.action):
    self.reset()
    return target

Engineering decisions

ADR: Per-axis slew-rate limiter
Status: Accepted
Context: RSK-05 — jerk between ~5 Hz VLA outputs and 10–100 Hz actuation.
Decision: Stateful CommandSmoother with configurable rates and STOP bypass.
Alternatives Rejected: moving average; fixed-duration lerp.
Consequences: Tune max_*_rate and heartbeat_hz together in sim.
