Dataset versioning and documentation

Epic: Dataset Generation, Labeling, and Validation (105) · Jira epic: VLA-6 · Story: VLA-47 / 1035 · Subtasks: 10105 (naming), 10106 (stats), 10107 (dataset card)

Human-readable version (browser): dataset-versioning.html

Executive summary

VLA-47 packages a processed dataset release under data/processed/vMAJOR.MINOR.PATCH/: validated JSONL splits, optional augmented images, machine-readable validation_report.json (from VLA-45), and human-readable DATASET_CARD.md. Version strings are validated before any path is constructed so typos cannot write outside the processed tree.

Mental model

Think of versioning as labeling a release artifact, not git-tagging source code.

It exists because training configs point at data/processed/v0.1.0/train.jsonl — without a version folder convention, teammates cannot reproduce which rows and QA stats a run used.

The key engineering tension is generated docs vs hand-written prose: the dataset card is rendered from live validation reports so it cannot drift from reality.

A beginner mistake is using 0.1.0 without the v prefix, or hand-editing validation_report.json after a failed validate.

A senior engineer watches for artifact lineage — stats must come from VLA-45, not ad-hoc builder counters.

Backstory: why this exists

Teams often dump train.jsonl in a shared folder and email a spreadsheet of counts. The naive approach loses coupling between QA results and the files Epic 106 actually loads.

That breaks when someone fixes JSONL without updating stats, or training points at latest/ with ambiguous contents.

So this design chooses semver-style directories, validator-generated JSON reports, and a rendered DATASET_CARD.md per version.

Implementation breakdown

Version naming (10105)

Snippet (litevla/data/versioning.py):

VERSION_PATTERN = re.compile(r"^v\d+\.\d+\.\d+$")

def processed_dir(version: str, *, repo_root=None) -> Path:
    if not is_valid_processed_version(version):
        raise ValueError(...)
    return repo_root / "data" / "processed" / version

Risks and gotchas: v0.1 or 0.1.0 are rejected — include the v prefix.

Stats and dataset card (10106 / 10107)

write_dataset_stats() writes validation_report.json. render_dataset_card() includes scope, limitations, label/source tables, and validation pass/fail summary.

Engineering decisions

ADR: Semver-style folder names (10105)
Status: Accepted
Decision: vMAJOR.MINOR.PATCH directory under data/processed/.
Alternatives Rejected: Date stamps only; unversioned latest/.

ADR: Stats from validator not builder (10106)
Status: Accepted
Decision: validation_report.json is output of validate_dataset, not builder counters.

Engineering principle taught by this task

Treat dataset releases like API versions. Folder name, config pointer, QA JSON, and human card should move together as one reproducible unit.
