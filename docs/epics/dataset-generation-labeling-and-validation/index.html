Dataset Generation, Labeling, and Validation

Image-instruction-action dataset for supervised fine-tuning — taught as a two-layer pipeline from raw sim logs to versioned training releases.

High-Level Epic Overview

Why Do We Need This Dataset?

Fine-tuning Vision-Language-Action (VLA) models requires high-quality training pairs where camera frames (observations) are coupled with natural language instructions (prompts) and corresponding motor commands (actions). Without a robust, standardized dataset, the robot cannot learn to associate visual obstacles with discrete navigation steering commands (such as MOVE_FORWARD or STOP). This epic establishes the complete pipeline for generating, validating, and loading this data.

How We Build the Dataset

Our dataset construction follows a robust two-layer pipeline:

  1. Layer A (Raw Capture): We record live keyboard teleoperation runs inside the Webots simulation, saving raw camera frames and steering commands alongside precise simulation-time clock timestamps.
  2. Layer B (Processed Compilation): A dataset builder compiles the raw logs, aligns unsynchronized visual frames with active commands using forward-fill semantics, applies photometric data augmentations to simulate lighting variances, and shuffles records deterministically into training and validation splits.
  3. Label Auditing & Validation: We export processed records to spreadsheet-friendly CSVs so humans can review, correct, or reject labels. Finally, automated validators verify file structures, duplicate IDs, and log category distributions to ensure dataset cleanliness.

Key Considerations to Keep in Mind

  • Vocabulary Consistency: Actions must strictly match the discrete steering vocabulary defined in our action schema. Typographical variations (like FORWARD instead of MOVE_FORWARD) will break model predictions.
  • Data Quality over Volume: Augmentations (contrast, brightness, random noise) help generalise the model but must be capped to prevent a single simulation run from dominating the dataset.
  • Deterministic Partitioning: Splitting data into train/val partitions must use fixed seeds so dataset splits are reproducible across test and training runs.

Epic ADR Log

Two-layer JSONL (VLA-41)

Status: Accepted

Decision: Raw capture shape ≠ training shape; builder is mandatory gate.

Sim-time join (VLA-42 → VLA-43)

Status: Accepted

Decision: Shared sim_stamp_sec/nanosec; forward-fill labels per frame.

Augment to 200 rows (VLA-43)

Status: Accepted (updated 2026-07-02)

Decision: Pillow variants on reference PNGs until teleop volume is sufficient; cap single-image dominance (25 variants when only one reference exists); scale per-image variants when multiple reference poses are present.

CSV review round-trip (VLA-44)

Status: Accepted

Decision: Export JSONL to CSV for spreadsheet review; import validates and sets manual_review provenance.

Validator before training (VLA-45)

Status: Accepted

Decision: Non-throwing validate_dataset collects all issues; CI uses --skip-image-check on fixtures-only checkouts.

Transform hook loader (VLA-46)

Status: Accepted

Decision: LiteVLADataset returns PIL + dict; Epic 106 training script supplies VLM-specific transform and collator.

Versioned processed releases (VLA-47)

Status: Accepted

Decision: vMAJOR.MINOR.PATCH folders with VLA-45 reports and generated DATASET_CARD.md; config points training at one version id.

One-command release (VLA-43–47)

Status: Accepted

Decision: scripts/run_dataset_release.sh chains build → review export → bulk-approve → import → validate with pending gate → version artifacts → loader smoke.
