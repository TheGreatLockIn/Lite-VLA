Epic 102

ROS 2 Simulation and Robot Control Skeleton

Build the non-ML robot loop that receives camera frames and publishes movement commands.

Intent | C4 context | Stories | ADR log

Epic Intent

Context: The paper routes model outputs through a ROS 2 bridge using velocity commands; this skeleton proves the robot path before adding ML.

Scope: Simulation environment, camera subscription, velocity publishing, dummy controller, heartbeat, and manual control.

Success criteria: Simulation runs; robot moves from dummy actions; camera frames are available; control loop remains stable without ML.

Epic 102 complete through VLA-28 — full robot skeleton ready for Epic 108 model integration.

Story 1012: Implement camera frame subscriber

VLA-24 — task doc

Intent
Receive camera frames from simulation or a physical camera; expose latest RGB array for downstream inference.

Data And Control Flow
flowchart LR
  CAM[/image_raw/] --> SUB[camera_subscriber]

ADR Notes

Story 1015: Add low-level control heartbeat

VLA-27 — task doc

Intent
Stable /cmd_vel publish rate independent of dummy/model update speed; safety timeouts.
Implementation Walkthrough
  • heartbeat_controller.py — timer, subscribes desired twist + action + camera
  • heartbeat_utils.py — timeout and diagnostics helpers
  • dummy_action_generator.py — refactored to publish /litevla/desired_twist only
  • launch/heartbeat.launch.py, updated dummy_sim.launch.py
  • test/test_heartbeat_utils.py
Data And Control Flow
flowchart LR
  DUMMY[dummy_action_generator] --> DES[/litevla/desired_twist/]
  CAM[/image_raw/] --> HB[heartbeat_controller]
  DES --> HB
  HB --> CMD[/cmd_vel/]
  HB --> DIAG[/litevla/diagnostics/]
ADR Notes

Decoupled rates: Action sources update asynchronously; heartbeat owns /cmd_vel.

STOP on timeout: Stale action or missing frames force zero velocity.

Validation

ros2 topic hz /cmd_vel
ros2 topic echo /litevla/diagnostics --once

Story 1016: Add manual teleoperation mode

VLA-28 — task doc

Intent
Human keyboard control for testing and dataset capture; overrides dummy when control_mode:=teleop.
Implementation Walkthrough
  • teleop_keyboard.py — TTY keyboard → /litevla/desired_twist
  • teleop_utils.py — key → discrete action map
  • command_recorder.py — JSONL under outputs/teleop/
  • scripts/run_teleop_sim.sh, scripts/stop_teleop_sim.sh — robust teleop lifecycle
  • launch/teleop_sim.launch.py, launch/webots_sim.launch.py (interactive GUI)
  • litevla_bridge/webots_launcher.py — drops --batch for teleop
  • test/test_teleop_utils.py
Data And Control Flow
flowchart LR
  KB[keyboard] --> TELEOP[teleop_keyboard]
  TELEOP --> DES[/litevla/desired_twist/]
  DES --> HB[heartbeat_controller]
  TELEOP --> REC[command_recorder]
  REC --> JSONL[outputs/teleop/*.jsonl]
ADR Notes

Keyboard MVP: Joystick deferred; sufficient for demo and dataset seeds.

Game-style keyboard: 50 Hz poll, per-key hold timeouts, s = reverse; combos (w+a) supported. Heartbeat 25 Hz / 200 ms action timeout for lower latency.

Robust teleop: Wheel-only Webots collision; interactive launch; readiness gates on /clock and controllers before keyboard starts.

Validation

./ros_ws/scripts/stop_teleop_sim.sh
ros2 launch litevla_bridge full_stack.launch.py control_mode:=dummy
ls outputs/teleop/*/commands.jsonl
